校园购物商城（CampusMall）— 项目说明书

一、项目概述

1.1 项目背景

本项目是数据库课程设计的实践项目，旨在设计并实现一个完整的校园购物商城系统。通过该项目，综合运用数据库设计（ER图、关系模式、范式分析）、SQL编程（存储过程、触发器、视图）、后端开发（Spring Boot + MyBatis）和前端开发（原生 HTML/CSS/JS）等技术，构建一个功能完善的电商平台原型。

1.2 项目目标

• 实现商品浏览、搜索、购物车、下单、支付、评价等核心电商功能

• 设计并实现包含 13 张核心表的规范化数据库

• 编写存储过程、触发器、视图等数据库高级对象

• 前后端分离架构，RESTful API 设计

• 模拟完整的购物流程闭环

二、技术架构

2.1 整体架构

项目采用经典的前后端分离架构：

┌─────────────────────┐     HTTP/JSON     ┌─────────────────────┐     SQL/JDBC     ┌─────────────┐
│     前端（静态页面）    │ ◄──────────────► │   后端（Spring Boot）  │ ◄──────────────► │  MySQL 数据库 │
│  HTML + CSS + JS     │    RESTful API   │  Spring Boot 2.7.18 │                  │  campus_mall │
│  原生 Fetch API      │                  │  MyBatis 2.3.1       │                  │             │
└─────────────────────┘                   └─────────────────────┘                  └─────────────┘

2.2 技术栈

层次 技术 版本 说明
**前端** HTML5 + CSS3 + JavaScript (ES6+) — 原生开发，无框架依赖
**后端框架** Spring Boot 2.7.18 自动配置、内嵌Tomcat
**ORM框架** MyBatis 2.3.1 XML映射 + 注解
**数据库** MySQL 5.7+ InnoDB引擎，支持事务
**构建工具** Maven — 依赖管理与打包
**JDK** Java 1.8 LTS版本
**Lombok** — — 简化实体类代码

2.3 后端分层架构

Controller（控制器层）
    ↓ 调用
Service（业务逻辑层）
    ↓ 调用
Mapper（数据访问层）← XML SQL映射
    ↓ JDBC
MySQL 数据库

每一层职责分明：

• Controller：接收HTTP请求，参数校验，调用Service，返回统一JSON响应

• Service：业务逻辑处理，事务管理，数据组装

• Mapper：数据库CRUD操作，SQL映射

• Entity：数据库表对应的Java实体

2.4 前端架构

前端采用原生HTML/CSS/JavaScript开发，通过 fetch API 调用后端 RESTful 接口。所有页面共用：

• css/style.css：全局CSS变量 + 组件样式

• js/api.js：API请求封装（含Token管理、Toast提示、工具函数）

• js/app.js：公共逻辑（导航栏渲染、登录状态检查、分页组件）

三、数据库设计

3.1 数据库概况

数据库名：campus_mall，字符集 utf8mb4，引擎 InnoDB。

共包含 13 张核心表、4 个存储过程、8 个触发器、8 个视图。

3.2 表结构详解

3.2.1 用户表（t_user）

字段 类型 说明
user_id INT, PK, AUTO_INCREMENT 用户ID
username VARCHAR(50), UNIQUE 用户名
password VARCHAR(100) 密码（BCrypt加密）
nickname VARCHAR(50) 昵称
avatar VARCHAR(255) 头像URL
phone VARCHAR(20) 手机号
email VARCHAR(100) 邮箱
balance DECIMAL(10,2) 账户余额
status TINYINT 0正常 / 1封禁
create_time DATETIME 创建时间
update_time DATETIME 更新时间（自动）

设计要点：余额字段用于模拟支付，status 字段支持账号封禁管理。

3.2.2 商品分类表（t_category）— 三级分类

字段 类型 说明
category_id INT, PK 分类ID
parent_id INT 父分类ID，0=顶级
name VARCHAR(50) 分类名称
level TINYINT 层级：1/2/3
sort_order INT 排序值
create_time DATETIME 创建时间

设计要点：采用邻接表模型实现无限层级分类，通过 parent_id 关联父节点，level 字段冗余存储层级深度便于查询。

3.2.3 商品SPU表（t_product）

字段 类型 说明
product_id INT, PK 商品ID
title VARCHAR(200) 商品标题
subtitle VARCHAR(200) 副标题
brand VARCHAR(50) 品牌
category_id INT, FK 三级分类ID
main_image VARCHAR(255) 主图URL
images TEXT 图片列表（JSON数组）
description TEXT 商品详情（富文本HTML）
status TINYINT 0下架 / 1在售 / 2待审核
create_time DATETIME 创建时间
update_time DATETIME 更新时间

设计要点：SPU（Standard Product Unit）与 SKU 分离设计。images 字段存储JSON格式的图片列表，description 存储HTML富文本。

3.2.4 商品SKU表（t_sku）

字段 类型 说明
sku_id INT, PK SKU ID
product_id INT, FK 所属SPU
spec_json VARCHAR(500) 规格JSON，如 `{"颜色":"黑色","容量":"256GB"}`
price DECIMAL(10,2) 售价
stock INT 库存
sku_image VARCHAR(255) SKU图片
status TINYINT 0禁用 / 1启用
create_time DATETIME 创建时间

设计要点：SKU（Stock Keeping Unit）是实际交易的最小单位。spec_json 以JSON格式存储规格组合，灵活支持不同品类的规格属性。

3.2.5 收货地址表（t_address）

字段 类型 说明
address_id INT, PK 地址ID
user_id INT, FK 用户ID
receiver_name VARCHAR(50) 收货人姓名
phone VARCHAR(20) 联系电话
province / city / district VARCHAR(50) 省市区
detail VARCHAR(200) 详细地址
is_default TINYINT 0否 / 1是默认
create_time DATETIME 创建时间

3.2.6 购物车表（t_cart）

字段 类型 说明
cart_id INT, PK 购物车项ID
user_id INT, FK 用户ID
sku_id INT, FK SKU ID
quantity INT 数量
checked TINYINT 0未选中 / 1选中
create_time DATETIME 创建时间

设计要点：UNIQUE KEY uk_user_sku (user_id, sku_id) 保证同一用户对同一SKU只有一条购物车记录，添加时累加数量。

3.2.7 订单表（t_order）

字段 类型 说明
order_id INT, PK 订单ID
order_no VARCHAR(50), UNIQUE 订单编号
user_id INT, FK 用户ID
total_amount DECIMAL(10,2) 商品总额
discount_amount DECIMAL(10,2) 优惠金额
pay_amount DECIMAL(10,2) 实付金额
coupon_id INT 使用的优惠券ID
address_snapshot TEXT 收货地址快照（JSON）
status TINYINT 0待付款/1待发货/2待收货/3已完成/4已取消/5已退款
remark VARCHAR(200) 买家留言
create_time DATETIME 下单时间
pay_time DATETIME 付款时间
ship_time DATETIME 发货时间
receive_time DATETIME 收货时间

设计要点：

• address_snapshot 存储下单时的地址快照JSON，防止用户修改地址后影响历史订单

• status 字段驱动订单状态机（0→1→2→3，或 0/1→4）

• 时间戳字段记录状态流转的关键节点

3.2.8 订单项表（t_order_item）

字段 类型 说明
item_id INT, PK 订单项ID
order_id INT, FK 订单ID
sku_id INT, FK SKU ID
product_title VARCHAR(200) 商品标题（快照）
sku_spec VARCHAR(500) 规格快照
sku_image VARCHAR(255) 图片快照
price DECIMAL(10,2) 下单时价格（快照）
quantity INT 数量
subtotal DECIMAL(10,2) 小计

设计要点：订单项采用冗余快照设计，将商品标题、规格、图片、价格在下单时固化到订单项中，确保即使商品信息变更也不影响历史订单展示。

3.2.9 支付记录表（t_payment）

字段 类型 说明
payment_id INT, PK 支付记录ID

pay_amount DECIMAL(10,2) 支付金额
pay_method TINYINT 1余额 / 2模拟支付
status TINYINT 0待支付 / 1成功 / 2失败
create_time DATETIME 创建时间

3.2.10 评价表（t_review）

字段 类型 说明
review_id INT, PK 评价ID

user_id INT, FK 用户ID

3.2.11 收藏表（t_favorite）

字段 类型 说明
favorite_id INT, PK 收藏ID
user_id INT, FK 用户ID
product_id INT, FK 商品ID
create_time DATETIME 创建时间

设计要点：UNIQUE KEY uk_user_product (user_id, product_id) 防止重复收藏。

3.2.12 优惠券表（t_coupon）

字段 类型 说明
coupon_id INT, PK 优惠券ID
name VARCHAR(100) 券名

discount_value DECIMAL(10,2) 优惠值（金额或折扣率）
min_amount DECIMAL(10,2) 最低消费门槛
total_count INT 发放总量

end_time DATETIME 有效期结束
status TINYINT 0禁用 / 1启用

3.2.13 用户优惠券表（t_user_coupon）

字段 类型 说明
id INT, PK 记录ID
user_id INT, FK 用户ID
coupon_id INT, FK 优惠券ID
status TINYINT 0未使用 / 1已使用 / 2已过期

设计要点：UNIQUE KEY uk_user_coupon (user_id, coupon_id) 限制每人每种优惠券只能领取一次。

t_order ──1:1──> t_review       （一个订单对应一条评价）

t_coupon ──1:N──> t_user_coupon （一张优惠券被多个用户领取）

3.5 存储过程

3.5.1 sp_create_order — 创建订单

功能：从购物车选中商品创建订单的完整事务流程。

参数：

• IN p_user_id — 用户ID

• IN p_address_id — 收货地址ID

• IN p_coupon_user_id — 用户优惠券ID（可为NULL）

• IN p_remark — 买家留言

• OUT p_order_id — 生成的订单ID

• OUT p_result — 操作结果消息

核心流程：

校验收货地址是否存在且属于该用户

计算购物车选中商品总额（SUM(price × quantity)）

处理优惠券：根据类型（满减/折扣/无门槛）计算折扣金额

生成唯一订单号（MALL + 时间戳 + 随机数）

创建订单记录

批量创建订单项（从购物车快照商品信息）

清空已下单的购物车商品

标记优惠券为已使用

全程事务管理，异常自动回滚

3.5.2 sp_pay_order — 支付订单

功能：模拟支付，支持余额支付和模拟直接成功。

核心流程：

校验订单状态为待付款（status=0）

余额支付：检查余额是否充足，扣减余额

模拟支付：直接标记成功

更新订单状态为待发货（status=1），记录支付时间

插入支付记录

3.5.3 sp_cancel_order — 取消订单

功能：取消订单并恢复库存。

核心流程：

校验订单状态为待付款或待发货（status=0或1）

更新订单状态为已取消（status=4）

通过游标遍历订单项，恢复每个SKU的库存

恢复用户优惠券状态为未使用

3.5.4 sp_confirm_receive — 确认收货

功能：确认收货，将订单状态从待收货(2)更新为已完成(3)，记录收货时间。

3.6 触发器

四、后端代码详解

4.1 启动与配置

4.1.1 ShopApplication.java

• 文件路径：backend/src/main/java/com/shop/ShopApplication.java

• 功能职责：Spring Boot 应用启动类

• 关键注解：

• @SpringBootApplication — 自动配置、组件扫描

• @MapperScan("com.shop.mapper") — 自动扫描并注册 Mapper 接口

• 启动方式：main() 方法调用 SpringApplication.run()

4.1.2 application.yml

• 文件路径：backend/src/main/resources/application.yml

• 功能职责：应用配置文件

• 关键配置：

• server.port: 8080 — 服务端口

• spring.datasource — MySQL 数据库连接（campus_mall 库）

• mybatis.mapper-locations — Mapper XML 文件位置

• mybatis.configuration.map-underscore-to-camel-case: true — 下划线自动转驼峰

• logging.level.com.shop: debug — 开发调试日志

4.1.3 WebConfig.java

• 文件路径：backend/src/main/java/com/shop/config/WebConfig.java

• 功能职责：Web MVC 全局配置

• 关键功能：

• 跨域配置：addCorsMappings() — 允许所有来源的跨域请求（开发环境）

• 拦截器注册：addInterceptors() — 注册 Token 认证拦截器

• 白名单：登录、注册、商品列表、商品详情、分类、优惠券等接口无需认证

4.1.4 TokenInterceptor.java

• 文件路径：backend/src/main/java/com/shop/config/TokenInterceptor.java

• 功能职责：Token 认证拦截器

• 关键逻辑：

• OPTIONS 请求直接放行（CORS 预检）

• 从 Authorization 头提取 Token

• 通过 TokenManager.getUserId() 验证 Token 有效性

• 验证失败返回 401 + 错误JSON

• 验证成功将 userId 存入 Request Attribute（currentUserId）

4.1.5 GlobalExceptionHandler.java

• 文件路径：backend/src/main/java/com/shop/config/GlobalExceptionHandler.java

• 功能职责：全局异常处理器

• 关键逻辑：

• RuntimeException → 返回 Result.error(message)

• Exception → 返回服务器内部错误

六、核心业务流程

6.1 用户注册与登录

用户 → register.html → POST /api/user/register
  → UserService.register()
    → 检查用户名唯一
    → 检查手机号唯一
    → 创建用户记录
  → 返回成功 → 跳转登录页

用户 → login.html → POST /api/user/login
  → UserService.login()
    → 校验用户名
    → 校验密码
    → 校验账号状态
  → TokenManager.generateToken(userId)
  → 返回 {token, user} → 前端存储到 localStorage

6.2 商品浏览与搜索

首页 → index.html
  → 渲染分类导航（GET /api/category/tree）
  → 加载商品列表（GET /api/product/list?keyword=&category_id=）
  → 渲染商品卡片网格
  → 用户点击 → 跳转 product.html?id=xxx

商品详情 → product.html
  → 加载商品信息（GET /api/product/{id}）
  → 加载SKU列表（GET /api/product/{id}/sku）
  → 解析spec_json为规格选项
  → 用户选择规格 → 匹配SKU → 更新价格/库存

6.3 购物车流程

加入购物车 → POST /api/cart/add {sku_id, quantity}
  → CartService.addToCart()
    → 检查库存
    → 检查是否已存在（累加数量 or 新增）
  → 返回成功 → 更新导航栏购物车角标

购物车页 → cart.html
  → 加载列表（GET /api/cart/list）
  → 前端渲染购物车项（含SKU信息、价格、小计）
  → 用户操作：
    - 调整数量 → PUT /api/cart/update
    - 选中/取消 → PUT /api/cart/update
    - 删除 → DELETE /api/cart/{id}
  → 实时计算总价
  → 去结算 → 跳转 checkout.html

6.4 下单与支付

结算页 → checkout.html
  → 并行加载：地址列表 + 购物车 + 可用优惠券
  → 用户选择：地址 + 优惠券
  → 前端计算折扣金额
  → 提交订单 → POST /api/order/create

后端创建订单流程（OrderService.createOrder）：
  ① 校验收货地址
  ② 获取选中购物车商品
  ③ 校验库存 → 计算总价
  ④ 扣减库存
  ⑤ 处理优惠券 → 计算实付金额
  ⑥ 生成订单号 → 创建订单记录（含地址快照）
  ⑦ 批量创建订单项
  ⑧ 清空已下单购物车
  ⑨ 返回订单详情

支付 → POST /api/payment/pay {order_id, pay_method}
  → PaymentService.pay()
    → 校验订单状态
    → 模拟支付成功
    → 记录支付信息
    → 更新订单状态为待发货(1)

6.5 订单状态机

         创建订单           支付              发货             确认收货
[待付款(0)] ────→ [待付款(0)] ──→ [待发货(1)] ──→ [待收货(2)] ──→ [已完成(3)]
    │                  │
    │ 取消订单         │ 取消订单
    ↓                  ↓
[已取消(4)]        [已取消(4)]

6.6 优惠券流程

领券中心 → coupon.html
  → 加载可领取优惠券（GET /api/coupon/available）
  → 加载我的优惠券（GET /api/user-coupon/my）
  → 领取 → POST /api/user-coupon/claim/{couponId}
    → CouponService.claimCoupon()
      → 校验优惠券状态、有效期、库存、重复领取
      → 创建用户优惠券记录
      → 更新已领取数量

下单时使用 → checkout.html
  → 选择优惠券 → 前端计算折扣
  → 提交订单时传入 userCouponId
  → OrderService.createOrder() 中调用 CouponService.useCouponById()
    → 校验未使用状态、有效期、最低消费
    → 标记为已使用

七、安全设计

7.1 认证机制

• Token 认证：基于 UUID Token 的简易认证方案

• Token 存储：后端使用 ConcurrentHashMap 内存存储，前端使用 localStorage

• 传递方式：Authorization: Bearer 请求头

• 拦截器：TokenInterceptor 拦截所有 /api/** 路径，白名单路径除外

7.2 接口权限

• 游客可访问：商品列表、商品详情、SKU列表、分类、优惠券列表

• 登录用户：购物车、订单、地址、收藏、评价、支付

• 管理员：商品上下架、数据统计（通过 AdminController）

7.3 数据安全

• 密码处理：数据库存储BCrypt哈希（测试数据中密码字段注释为BCrypt），但实际注册/登录代码中为明文比较（注释说明"实际项目中应加密存储"）

• 敏感信息过滤：UserController.sanitizeUser() 在返回用户信息时将 password 字段置空

• 地址快照：订单中的收货地址为JSON快照，防止历史订单信息被修改

7.4 业务安全

• 库存防超卖：

• 触发器 trg_order_check_stock 在插入订单项前校验库存

• Service 层在创建订单时也校验库存

• 数据一致性：

• 订单创建使用 @Transactional 事务管理

• 存储过程使用 START TRANSACTION + COMMIT/ROLLBACK

• 操作校验：

• 购物车操作校验用户归属

• 订单操作校验用户归属和状态合法性

• 评价校验订单状态和重复评价

• 优惠券校验有效期、使用条件、重复领取

7.5 跨域安全

• 开发环境配置 allowedOriginPatterns("*") 允许所有来源

• 生产环境应限制为特定域名

7.6 已知安全限制（课程设计说明）

• Token 存储在内存中，重启丢失（生产环境应使用 JWT + Redis）

• 密码未加密存储（生产环境应使用 BCrypt）

• 无 CSRF 防护（前后端分离+Token认证可缓解）

• 无接口限流（生产环境应添加 Rate Limiting）

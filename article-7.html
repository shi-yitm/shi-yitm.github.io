用 Node.js 从零搭建个人博客后台管理系统

📅 2026-06-05 👁 0 次阅读 #Node.js #Express #SQLite #博客 #GitHub Pages #CMS

你是否也厌倦了每次更新博客都要手动改 HTML、跑 git 命令？本文记录了我用 Node.js + Express + SQLite 搭建博客 CMS 的全过程，包括后台管理、Markdown 编辑器、自动部署到 GitHub Pages 的完整实现，以及踩坑经验。

为什么需要一个后台管理系统

之前的博客是纯静态 HTML 页面，每次更新文章的流程是：打开编辑器 → 改 HTML 代码 → git add → git commit → git push。不仅繁琐，而且写文章的体验很差——在代码里写中文内容，连个预览都没有。

这次的目标很明确：

  • 在浏览器里写文章，支持 Markdown 实时预览
  • 文章的增删改查，分类管理
  • 写完一键部署到 GitHub Pages
  • 技术栈尽量简单，一个人能搞定

技术选型：为什么选 Node.js + SQLite

组件 选择 理由
后端 Node.js + Express 轻量好理解，前后端语言统一
数据库 SQLite（better-sqlite3） 就是一个文件，不用装数据库服务
前端 原生 HTML/CSS/JS 够用就行，不搞复杂框架
Markdown marked.js 成熟的 Markdown 渲染库
部署 GitHub Pages 免费、稳定、自动 HTTPS

选 SQLite 的最大好处是数据就是一个 .db 文件，跟着项目走，复制文件就等于备份数据库。选 Node.js 是因为前后端都用 JavaScript，学习成本最低，不用切换语言。

核心功能实现

后台管理面板

后台用左右布局：左侧菜单栏（文章管理、写文章、背景设置），右侧内容区。

文章管理用表格展示所有文章，显示标题、分类、状态（已发布/草稿）、阅读量。支持编辑和删除，顶部有统计卡片展示总文章数、已发布数、草稿数和总阅读量。

Markdown 编辑器是核心功能。采用左右分屏设计，左边写 Markdown 源码，右边实时预览渲染效果。用 marked.js 做渲染引擎，支持标题、加粗、代码块、引用、列表、表格等常用语法。写完立刻能看到最终效果，体验比改 HTML 好太多。

API 接口设计

后端用 Express 提供 RESTful API：

GET    /api/articles          获取文章列表（支持分页、分类筛选）
GET    /api/articles/:id      获取单篇文章
POST   /api/articles          新建文章
PUT    /api/articles/:id      更新文章
DELETE /api/articles/:id      删除文章
GET    /api/articles/meta/categories  获取所有分类

前端通过 fetch() 调用这些接口，实现文章的增删改查。数据库用 better-sqlite3 的同步 API，代码非常简洁。

一键部署

写了一个 deploy.js 脚本，一条命令完成整个部署流程：

  1. 从 SQLite 数据库读取所有已发布文章
  2. 用 marked 库把 Markdown 渲染成 HTML
  3. 套用网站模板生成静态页面
  4. git add → git commit → git push
  5. GitHub Pages 自动更新

整个过程几秒钟搞定，从"写完文章"到"线上更新"只需要说一句"部署一下"。

踩坑记录

样式文件被覆盖

最开始部署时，不小心把博客原有的 style.css 覆盖成了后台管理的样式，导致前台页面排版全乱——导航栏变成竖排、文章卡片变成单列。花了好一会儿才从 git 历史里恢复。

教训：部署脚本只生成 HTML 文件，永远不要动 CSS 和 JS。后来在脚本里加了严格限制，确保只写 HTML。

Markdown 转换的坑

一开始手写了个正则表达式做 Markdown 转 HTML，结果把 <h2>、<ul>、<blockquote> 都包在了 <p> 标签里，排版完全错乱。后来换成了 marked 库，一行 marked.parse(md) 解决所有问题。

教训：不要重复造轮子，成熟的库经过了大量测试，比自己写的正则靠谱得多。

毛玻璃对比度问题

背景用了流体艺术风格的图片，色彩很丰富。最初用白色毛玻璃做卡片背景，结果在深色区域文字完全看不清。后来改成深色毛玻璃 + 白色文字，才达到 WCAG 对比度标准（正文至少 4.5:1）。

教训：做半透明 UI 时，一定要在最亮和最暗的背景上都测试文字可读性，不能只看一种情况。

总结

这套系统虽然简单，但覆盖了博客的核心需求。现在写博客的流程变成了：

打开后台 → 写 Markdown → 点保存 → 说"部署一下" → 自动上线

从繁琐的代码操作变成了纯粹的写作体验。

技术栈总结：Node.js + Express + SQLite + marked.js + GitHub Pages。整个项目一个人就能搞定，代码量不大，但学到了很多前后端分离、API 设计、数据库操作、静态部署的知识。

如果你也想搭一个类似的系统，建议从最简单的功能开始——先能写文章、能展示，再慢慢加分类、标签、背景设置这些。技术选型不用纠结，能解决问题的就是好方案。

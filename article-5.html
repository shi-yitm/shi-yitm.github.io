用 Node.js 从零搭建个人博客后台管理系统

📅 2026-06-07👁 0 次阅读

为什么自己搭后台

GitHub Pages 托管静态博客很方便，但每次写文章都要手动创建 HTML 文件，太麻烦了。于是决定用 Node.js 搭一个后台管理系统。

技术栈

  • Express：轻量级 Node.js Web 框架
  • sql.js：基于 WASM 的 SQLite，零配置嵌入式数据库
  • marked.js：Markdown 渲染
  • Nginx：反向代理，前端静态页面 + 后台 API 转发
  • systemd：进程守护，开机自启

架构演进

第一版：本地 CMS + 远程部署

最初的设计是 CMS 跑在本地 Windows 电脑上，文章存在本地 SQLite 数据库里。每次写完文章，deploy.js 读取本地数据库，生成静态 HTML，通过 SCP 上传到腾讯云服务器。

这个方案的问题很明显：文章只存在本地电脑上，服务器只是静态文件的"副本"。一旦本地数据库损坏或不同步，服务器上的内容就会出问题。

第二版：服务器端 CMS（当前版本）

把 CMS 直接部署到腾讯云服务器上：

浏览器 → Nginx (80端口)
  ├── / → /var/www/blog/ (前台静态页面)
  ├── /admin → 127.0.0.1:3000 (后台管理)
  └── /api → 127.0.0.1:3000 (文章/项目 API)
  • 文章数据直接存在服务器的 SQLite 数据库里
  • 后台管理通过 /admin 路径访问，有密码保护
  • 前台博客仍然是静态 HTML，性能好
  • systemd 管理 Node.js 进程，崩溃自动重启

核心功能

  1. 文章管理：新增、编辑、删除、拖拽排序、隐藏/显示
  2. 项目管理：维护个人项目展示
  3. 分类与标签：文章分类管理
  4. 阅读量统计
  5. Markdown 编辑器：实时预览
  6. 密码保护：后台登录验证

安全设计

  • 后台管理需要密码登录，API 也必须带认证头
  • 前台博客是纯静态文件，不暴露任何 API
  • Nginx 屏蔽隐藏文件访问

部署方式

# systemd 服务
/etc/systemd/system/blog-cms.service
# 开机自启
systemctl enable blog-cms
# 查看状态
systemctl status blog-cms

总结

从本地部署到服务器端 CMS，这个过程让我理解了 Web 应用的完整生命周期：开发、部署、运维、版本控制。特别是从"本地+远程"架构迁移到"纯服务器"架构的经验，对理解前后端分离和部署很有帮助。

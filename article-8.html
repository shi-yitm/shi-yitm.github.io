用 Python 手搓一个 Windows 桌面小组件：DeepSeek API 用量实时监控

📅 2026-06-10👁 1 次阅读 #Python #pywebview #DeepSeek #桌面小组件 #Windows #教程

背景

我日常重度依赖 DeepSeek，高频使用的时候一天能跑几百块。每次想查余额和用量，都要打开网页、登录后台、点好几层菜单——用久了真的很烦。

正好 GitHub 上有个开源项目 tristan-mcinnis/Deepseek-API-Balance-Checker，提供了 API 数据采集的思路。我让 AI 帮我基于它写了一个 Windows 桌面小组件，钉在屏幕右上角，瞄一眼就知道今天跑了多少、还剩多少钱。

这篇文章记录我从 Tkinter 到 pywebview 的完整选型、开发与踩坑过程。如果你想自己做一个桌面小组件（不限于 API 监控），这篇文章应该能帮你少走不少弯路。

成品效果

最终成品是一个 366×562 像素的暗色小组件，无边框、始终置顶、可拖动。上半部分显示实时余额和 Token 用量进度条，中间排列会话用量、今日用量、缓存命中率等卡片，下半部分是按模型分解的用量条和近 7 天柱状图。数据每 5 秒自动刷新，不需要任何手动操作。

技术架构

项目分为两层，职责清晰：

  • 数据采集层（fetch_balance.py）：每 30 秒向 DeepSeek API 请求一次，拉取余额、总用量、按模型分解、缓存命中/未命中、近 7 天用量等数据，写入 balance.json。这部分沿用 Codex 之前写好的实现，不做改动。
  • UI 展示层（widget.html + widget_test.py）：HTML / CSS / JavaScript 负责前端渲染，pywebview 提供桌面窗口壳。数据通过 JS Bridge 从 balance.json 读取，每 5 秒刷新一次 DOM。

数据流非常简洁：

DeepSeek API → fetch_balance.py → balance.json → JS Bridge → widget.html

UI 选型：为什么是 pywebview

第一版用的是 Tkinter——Python 自带的 GUI 库。出来的效果怎么说呢，大概就是 Windows 95 控制面板的白底黑字风格，方方正正，毫无美感可言。而我要的是 Windows 11 小组件那种暗色玻璃拟态：半透明卡片、柔和圆角、精致的阴影。

我考察了以下方案：

方案 优点 缺点
Tkinter Python 自带，零依赖 现代化 UI 极其痛苦，控件自由度极低
Electron 效果精美，生态丰富 一个小组件就要 150MB，太重型
Tauri 比 Electron 轻量很多 需要 Rust 工具链，学习曲线陡峭
pywebview 用系统自带 WebView 渲染，包不到 10MB 文档和边缘 case 需要自己踩坑

最终选 pywebview 的理由很直接：能用 HTML/CSS/JS 写界面（玻璃拟态、动画、图表随便折腾），Python 环境现成，不需要额外装 Node.js 或 Rust 工具链。

踩坑实录

pywebview 看起来美好，实际踩坑不少。下面是过程中遇到的五个典型问题及其解法。

坑一：GUI 后端自动检测失败

pywebview 在 Windows 上默认使用 Edge WebView2 渲染。但我的 Python 3.13 环境中，webview.guilib 的自动检测结果是 None——识别机制挂了。

解决：手动强制初始化。

from webview.guilib import initialize
initialize()  # 强制检测，返回 winforms 后端

坑二：start() 函数签名容易写错

pywebview v6 的 webview.start() 第一个参数是 callable，不是 js_api 对象——这个很容易被文档误导。

# ❌ 错误写法
webview.start(api, gui="winforms")

# ✅ 正确写法：js_api 在 create_window 时传入
window = webview.create_window("Title", html=html, js_api=api)
webview.start(gui="winforms")

坑三：CORS 与 HTTP Server 端口冲突

pywebview 自带一个内部 HTTP Server。如果自己再起一个同端口的服务，直接冲突报错。Python 的 socketserver 和 pywebview 的 Bottle Server 不能共用一个端口。

最终方案：彻底放弃自主 HTTP Server，数据完全通过 JS Bridge 传递。Python 端暴露 get_data() 方法直接读 balance.json 返回字符串，HTML 端用 window.pywebview.api.get_data() 异步获取。这样不仅绕过了端口冲突，连 CORS 问题也一并消失了。

JavaScript 端：

async function refresh() {
    const raw = await window.pywebview.api.get_data();
    const data = JSON.parse(raw);
    // 更新 DOM 元素...
}

Python 端：

class Api:
    def get_data(self):
        with open("balance.json", "r") as f:
            return f.read()

坑四：debug=True 弹出 DevTools

开发阶段开 debug=True 方便调试，结果忘了关——生产环境用户看到的是一个 Chrome DevTools 窗口加一个空白页面。关掉 debug=False 立马恢复正常。

坑五：WinForms WebBrowser 控件不懂现代 CSS

某个中间版本我试图绕过 pywebview，直接用 pythonnet + WinForms WebBrowser 控件来嵌入页面。结果发现这个控件的底层是 IE 引擎——CSS 变量（var(--bg)）、rgba()、Flexbox 全都不认。页面渲染出来是白底黑字，跟没写 CSS 一样。果断回到 pywebview 的 Edge WebView2 引擎。

核心实现要点

无边框、置顶、可拖动的桌面窗口

window = webview.create_window(
    "DeepSeek Monitor",
    html=html,
    js_api=api,
    width=366, height=562,
    frameless=True,      # 无标题栏
    on_top=True,         # 始终置顶
    easy_drag=True,      # 可拖动（这参数是关键）
    background_color="#0d1117",
)

easy_drag=True 让 frameless 窗口也能直接用鼠标拖动，不需要自己处理 WM_NCHITTEST 消息。

最小化与关闭按钮

HTML 按钮通过 JS Bridge 调用 Python 端方法：

<button onclick="minimize()">−</button>
<button onclick="closeWidget()">✕</button>

function minimize() { window.pywebview.api.minimize(); }
function closeWidget() { window.pywebview.api.close_window(); }

玻璃拟态暗色主题

用 CSS 变量集中管理主题色，卡片使用半透明背景 + 细边框：

:root {
    --bg: #0d1117;
    --card: rgba(22, 27, 34, 0.92);
    --border: rgba(48, 54, 61, 0.6);
    --text: #e6edf3;
    --accent: #58a6ff;
}
.card {
    background: rgba(255, 255, 255, 0.03);
    border: 1px solid var(--border);
    border-radius: 8px;
}

纯 CSS 近 7 天柱状图

不引入 Chart.js 等额外依赖，直接用 div 的高度来表示每日用量占比：

const days = data.seven_days || [];
const maxV = Math.max(...days.map(d => d.tokens), 1);
for (const d of days) {
    const h = Math.max((d.tokens / maxV) * 52, 2);
    chartHtml += `<div class="chart-bar" style="height:${h}px"></div>`;
}

项目启动

双击 start-monitor.bat 即可启动：

start /min python fetch_balance.py    # 后台采集数据
python widget_test.py                  # 桌面小组件窗口

常见问题

窗口不出现怎么办？

确保安装了 Edge WebView2 Runtime（Windows 11 自带，Windows 10 需手动安装）。运行 python widget_test.py 查看终端报错。

数据不更新？

检查 fetch_balance.py 是否在后台运行，以及 .env 中的 api_key 是否正确。

能不能自定义颜色和刷新频率？

可以。颜色在 widget.html 的 :root CSS 变量中修改，刷新频率改文件末尾的 setInterval(refresh, 5000) 即可。

总结

整个项目从决策到落地大约花了两个小时，其中至少一个半小时在踩 pywebview 的各种坑。但做完之后确实好用——瞄一眼桌面右上角，就知道 API 跑了多少、还剩多少钱。

几条关键经验：

  1. pywebview 是 Python 生态里做小型桌面工具的最优解之一，比 Electron 轻十倍以上
  2. 用 JS Bridge 传数据比自己搭 HTTP Server 简单可靠得多，天然免疫 CORS 和端口冲突
  3. 先跑通最简配置，再逐步加功能——frameless、on_top、easy_drag 一起上容易出幺蛾子
  4. Edge WebView2 是现代 Web 标准的保障，WinForms 内嵌的 IE 控件可以安心扔进历史垃圾桶了

项目代码已开源在 GitHub：shi-yitm/deepseek-monitor-widget，欢迎 Star ⭐

如果你也想做一个桌面小组件，我的建议是：从 pywebview 官方最简单的示例入手，先跑通一个带标题栏的普通窗口，再逐步叠加 frameless、on_top、自定义拖动等功能。别学我一开始就往死里叠 buff——那是我两个小时踩坑生涯的「精华」所在。

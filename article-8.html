用 DeepSeek 免费跑 Codex CLI：CC-Switch 协议转换部署指南

📅 2026-06-07 👁 0 次阅读 #Codex CLI #DeepSeek #CC-Switch #AI编程 #Windows

为什么不能直接改 base_url

很多人第一反应肯定是：DeepSeek 不是兼容 OpenAI 的 API 吗，那把 Codex 的 base_url 改成 https://api.deepseek.com 不就行了？

真不行。至少现在还不行。

Codex CLI 用的是 OpenAI 较新的 Responses API 协议——这是 OpenAI 为 agent 类应用专门设计的接口，支持多轮会话、工具调用、流式 SSE 这些高级能力。而 DeepSeek 官方 API 是基于 Chat Completions 协议，这是更早的对话补全接口。两者虽然看起来都是"OpenAI 风格"，但底层请求结构、参数名、SSE 事件格式都不一样。

直接改 base_url 会踩的坑：

  • 请求路径返回 404
  • 多轮对话时上下文串不起来
  • 工具调用（tool calls）解析出错
  • SSE 流式事件格式对不上
  • 单轮问答能通，一跑实际任务就挂

所以必须有一个协议翻译层在中间做转换。

方案对比：CC-Switch vs OpenRouter

CC-Switch（本地代理）

开源项目 ccswitch-deepseek，一个轻量的 Node.js HTTP 代理。在本地跑一个 index.js，监听 11437 端口，负责把 Codex 发来的 Responses API 请求翻译成 Chat Completions 格式再发给 DeepSeek，回来的时候再转回去。

优点：全本地运行，零数据泄露，延迟低 缺点：需要自己启动和维护代理进程

OpenRouter BYOK

OpenRouter 是个第三方 API 路由服务，BYOK（Bring Your Own Key）模式能绑定你自己的 DeepSeek API Key 由它做协议转换。

优点：不用跑本地服务 缺点：多一层网络延迟，API Key 和数据需要经过第三方

Windows 下的完整部署

前置条件

  1. Node.js——装 LTS 版本
  2. DeepSeek API Key——在 platform.deepseek.com 注册获取
  3. Codex CLI——全局安装：npm i -g @openai/codex

第一步：装 CC-Switch

git clone https://github.com/liuzhengming/ccswitch-deepseek.git D:\ccswitch-deepseek
cd D:\ccswitch-deepseek
npm install

第二步：配置 API Key

在 D:\ccswitch-deepseek\ 下创建 .env：

api_key=sk-your-key
DEEPSEEK_API_KEY=sk-your-key
model=deepseek-v4-pro
port=11437

改 index.js 让 .env 加载路径变成绝对路径：

dotenv.config({ path: "D:/ccswitch-deepseek/.env" });

第三步：配置 Codex Profile

在 C:\Users\你的用户名\.codex\ 下创建 deepseek-local.config.toml：

model = "deepseek-v4-pro"
model_provider = "ccx-bridge"

[model_providers.ccx-bridge]
name = "CCX Bridge (DeepSeek)"
base_url = "http://127.0.0.1:11437/v1"
env_key = "DEEPSEEK_API_KEY"

第四步：启动

一个窗口跑代理：

D:\nodejs\node.exe D:\ccswitch-deepseek\index.js

另一个窗口跑 Codex：

set DEEPSEEK_API_KEY=sk-your-key
codex --profile deepseek-local

第五步：一键启动脚本

每次开两个窗口还是有点烦，写一个 run-codex.bat：

@echo off
set "DEEPSEEK_API_KEY=sk-your-key"
taskkill /f /im node.exe >nul 2>&1
start "Proxy" /min D:\nodejs\node.exe D:\ccswitch-deepseek\index.js
ping -n 4 127.0.0.1 >nul
codex --profile deepseek-local
taskkill /f /im node.exe >nul 2>&1

保存后放到桌面快捷方式，双击即可一键启动。

踩坑记录

"UNC 路径"错误

从 WSL/PowerShell 启动 Codex 时，工作目录继承了 \\wsl.localhost\... 这种路径，Windows CMD 不支持。解决：codex.cmd ... -C D:\ 或 bat 里先 pushd D:\。

端口被占用

重复启动代理会报 EADDRINUSE。脚本里的 taskkill /f /im node.exe 自动清理残留。

环境变量传不过去

set DEEPSEEK_API_KEY=... 必须放在启动 Codex 的同一个 CMD 进程里。

验证

在 Codex 里问一句"你是谁"，如果回答"我是 DeepSeek"就说明一切正常。我从实际运行中验证过，V4 Pro 和 V4 Flash 都能正常工作。
